# Transport responsiveness tracklist

Updated: 2026-09-10. Starting commit: daa3aa53707ad21b55338369c1d9cecfec5e0504. The existing unrelated working-tree changes are preserved. Task-local source snapshots and command records are in `benchmark-results/.work/responsiveness-20260908/` and `benchmark-results/.work/acceptance-20260909/`.

## Acceptance

Measure direct H3/QUIC DATAGRAM, H2 and WSS against Linux kernel WireGuard on the same VM/network, effective overlay MTU 1340, underlay MTU 1500, 40 ms netem delay per direction, configured 0.1% loss, four inner BBR TCP load flows and equal TCP autotuning ceilings. Preserve TLS exporter/Noise authentication and the captured browser-family ClientHello profile. WSS is the TLS-protected WebSocket path; plaintext WS remains a diagnostic control where useful.

The loaded p95 and p99 RTT in each direction must each be <= 1.10 times the corresponding new WireGuard result. Report median as well. Track delivery, overdue/missing probes, throughput, retransmissions, CPU and RSS. Use both ICMP and independent small application requests so priority for one probe protocol alone cannot establish completion. Retain the H2/WSS 5 Gbit/s receiver-goodput milestone and compare full baseline throughput; explicitly report any throughput tradeoff. Three final trials per direction, 30 seconds measured after 10 seconds warm-up; no simultaneous builds or competing benchmarks. Fixed-rate and unrestricted load tests answer different questions and must be labeled separately. Offloads and qdisc placement are recorded, including their limitations.
