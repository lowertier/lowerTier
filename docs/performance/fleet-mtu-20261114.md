## Source contract and selection

`effective_nic_mtu()` in `lowertier/src/instance/virtual_nic.rs`
subtracts 20 bytes from `tun.mtu` for the retained kernel adapters.
None of the retained fleet instances enables native Ethernet bridging.
Native Ethernet bridging has a separate minimum of 1516 bytes.

`get_proxy_listener()` in `lowertier/src/gateway/tcp_proxy.rs`
sets the userspace TCP device MTU to 1280.
Changing `tun.mtu` does not change that device capability.
The separate SOCKS stack in `lowertier/src/gateway/socks5.rs` uses MTU 1284
to align IPv4 fragment payloads.
The fleet policy does not change that internal proxy implementation.
Userspace nodes have no kernel overlay interface.

Thus, a configured userspace MTU of 1360 does not establish an effective TCP MTU of 1360.
The selected policy aligns kernel interfaces with the existing userspace TCP device.
It also leaves more encapsulation headroom than the tested native MTU 1360.

QUIC starts with a 1200-byte UDP payload limit.
It discovers its outer path MTU independently.
Recorded paths include UDP payload limits of 1452 and 1357 bytes.
These limits are outer QUIC values, not overlay interface MTUs.
LowTier splits oversized packets across DATAGRAM frames.
Losing one fragment can lose the overlay packet.
MTU 1280 does not guarantee that every outer path avoids fragmentation.

Relevant code:

- `lowertier/src/instance/virtual_nic.rs`: effective kernel MTU and bridge exception.
- `lowertier/src/gateway/tcp_proxy.rs`: fixed userspace TCP device capability.
- `lowertier/src/gateway/socks5.rs`: separate fragment-aligned proxy capability.
- `lowertier/src/tunnel/quic.rs`: outer MTU, framing, and fragmentation.
- `lowertier/src/tunnel/quic/fragments.rs`: fragment reassembly.

## Cost model

The original Mac interface used MTU 1280.
The original s6916 interface used MTU 1260.
Their TCP trials reported MSS 1208.
The native MTU 1360 candidate reported MSS 1308.
The common MTU 1280 reports MSS 1228 on this host pair.

At 500 Mbit/s, full data segments require approximately:

| TCP MSS, bytes | Data segments per second |
| ---: | ---: |
| 1208 | 51,738 |
| 1228 | 50,896 |
| 1308 | 47,783 |

MTU 1280 reduces this segment count by approximately 1.63 percent against the original s6916 path.
It requires approximately 6.51 percent more segments than the native MTU 1360 candidate.
These counts exclude acknowledgements, retransmissions, and outer fragmentation.
They predict packet-processing work, not a guaranteed throughput change.

At 12 ms RTT, 500 Mbit/s requires approximately 750,000 payload bytes in flight.
This deployment does not change flight limits, queue byte limits, or pacing.
Larger packets alone do not remove those separate constraints.

## Measurement method

The main path is the native Mac at `10.126.126.2` to s6916 at `10.126.126.60`.
Each TCP trial uses two warmup seconds and ten measurement seconds.
Each matrix cell has two repetitions in each direction.
QUIC also includes four-stream trials.
H2 and WSS use one stream.
The server retains the original iperf service on port 5201.

The additional exit-node path targets `10.126.126.82`.
Its temporary iperf server uses overlay port 15209.
Automatic transport selection remains active for those exit-node observations.
The recorded data transport must match before results can support an MTU comparison.

Rates use receiver payload bytes and receiver duration.
Each successful throughput trial requires all fourteen concurrent ICMP replies.
TCP retransmission values come from the iperf sender summary.
They are platform counters, not an independently measured wire loss rate.

Process resource sampling uses a 0.5-second interval for approximately fifteen seconds.
CPU cost divides sampled LowTier user and system time by measured receiver Gbit.
The sample window includes warmup and collection time.
It also includes background LowTier work.
It excludes iperf CPU time and uncharged kernel work.
RSS covers process resident memory, not kernel buffers.
No WireGuard comparison is claimed.

Common-MTU transport trials refresh local route state after the server restart.
An exact 8 MiB transfer in each direction precedes those trials.
The earlier matrix lacks that application preconditioning.
These conditions do not support a matched cold-start comparison.
