# QUIC admission and WSS measurements on jpaws–LA

The tests support `auto` as the QUIC admission default.
It adds capacity fallback and refusal cooldown to the existing native stream path.
It does not establish isolation from stalled native streams.
Four unread native downloads blocked later native requests, packet fallback, and concurrent UDP probes.
This limit remains unresolved.

No additional QUIC multiplexer was added.
WSS retains its current packet path.
The implementation also repairs early release of native stream permits in H2 and QUIC.

## Scope and method

Measurements ran on November 17, 2026.
Both test endpoints used userspace mode on jpaws and LA.
The configured overlay MTU was 1300.
The userspace TCP device used MTU 1280.
QUIC diagnostics reported MTU 1452 on the public path.
These values describe different layers.

All application connections started through the jpaws SOCKS endpoint.
GET means LA → jpaws data.
PUT means jpaws → LA data.
This does not test server-initiated native proxy admission.
The native scope requires the remote userspace peer's own IPv4 address.
Kernel TUN forwarding, routed destinations, and ACL-controlled traffic retain packets.

The primary matrix contains 66 bulk trials:

- Healthy QUIC: three modes, two flow counts, two directions, and three rotated repeats.
- Injected-loss QUIC: three modes, one flow, two directions, and three rotated repeats.
- Healthy WSS: one packet mode, two flow counts, two directions, and three repeats.

Each healthy trial transferred 64 MiB.
Each loss trial transferred 16 MiB.
The receiver checked the complete byte pattern.
Bulk timing excludes SOCKS admission and carrier setup.
Eleven unloaded echo samples preceded each bulk transfer.
A separate TCP echo stream measured loaded latency.
Concurrent UDP probes used a 500 ms reply deadline.

Each mode cohort started a fresh authenticated carrier.
The healthy case order was one-flow GET, one-flow PUT, four-flow GET, and four-flow PUT.
Later cases reused that carrier.
The mode order rotated between repeats.
The tables show medians and complete minimum-to-maximum ranges.
Three WAN repeats do not establish a causal speed difference between `on` and `auto`.

CPU values sum user and system CPU from both LowTier daemon processes.
They divide that sum by delivered application Gbit.
They exclude generators, the destination service, the loss relay, and unrelated kernel work.
Server sampling includes the control interval and unloaded probes.
Client CPU sampling starts before bulk transfer.
RSS samples occur every 100 ms.
They do not establish allocation peaks or kernel socket memory.

## Admission reliability and setup cost

Each healthy, capacity, or refusal cohort sent twelve new 4 KiB requests.
Each mode had three repeats.
The capacity case held 32 admitted native streams before the new requests.
The refusal case disabled native admission at the remote endpoint after carrier authentication.

| Case | Mode | Delivered requests | Median successful completion ms |
| --- | --- | ---: | ---: |
| Healthy | off | 36/36 | 445.31 |
| Healthy | on | 36/36 | 220.48 |
| Healthy | auto | 36/36 | 224.22 |
| Capacity | on | 0/36 | — |
| Capacity | auto | 36/36 | 435.61 |
| Remote refusal | off | 36/36 | 434.41 |
| Remote refusal | on | 0/36 | — |
| Remote refusal | auto | 36/36 | 459.20 |

Strict `on` refusal is the expected result in the two pressure cases.
The `auto` capacity decisions selected packets before CONNECT.
Remote refusal produced six native attempts and thirty cooldown selections across 36 requests.
Native admission recovered after capacity or remote support returned.

The healthy setup median differed by 3.74 ms between `auto` and `on`.
This WAN comparison does not isolate mutex CPU cost.
The short-flow timing includes SOCKS setup, admission, and application delivery.
The bulk timing excludes admission.

The previous QUIC implementation already attempted eligible native streams.
These native-versus-packet speed differences are not new gains created by the policy.
The comparison uses one repaired candidate with different modes.
It does not measure an old installed binary against a new release.

## Slow-reader failure

Each cohort opened four 32 MiB downloads and stopped reading them.
The requested application receive buffer was 32768 bytes.
Linux reported 65536 bytes per socket.
After five seconds, the client sent two short requests.
Three repeats produced these results:

| Mode | Delivered short requests | UDP replies within 500 ms | Coverage |
| --- | ---: | ---: | --- |
| off | 6/6 | 118/118 | Complete |
| on | 0/6 | 38/127 | One collector stopped on a late reply |
| auto | 0/6 | 43/173 | Complete |

Every `auto` repeat selected packets for its second request during native cooldown.
That fallback also timed out.
The background downloads were intentionally cancelled.
Their incomplete payloads are not counted as successful deliveries.

One follow-up closed the unread transfers before a new request.
The new native request delivered 4096 bytes in 236.58 ms.
It used the same QUIC connection.
The result supports temporary pressure rather than permanent carrier failure.
It does not establish universal recovery behavior.

Source inspection identifies two concrete coupling paths:

- The packet writer waits for reliable completion before it accepts later DATAGRAM batches.
- A selected CONNECT-IP write delays reads on that stream.

Shared connection-credit exhaustion can trigger those dependencies.
The experiment did not record active `MAX_DATA`, `data_sent`, or the exact blocked write.
The complete causal chain remains an inference.
The logged `send_buffer_space` describes DATAGRAM storage, not STREAM send credit.

Admission cooldown cannot free occupied connection credit.
Packet fallback on that carrier cannot provide independent progress while the shared writer waits.
Changes to `tcp_proxy` affect new flows and do not cancel admitted streams.
Protected control capacity and independent scheduling need separate implementation and validation.

## Injected-loss QUIC

The relay injected drops with probability 0.01 in each direction.
Every cohort used seed 20261117.
The public WAN can add further loss and delay.
This is not an exact-total-loss synthetic link.

The first relay used its default receive buffer and overflowed.
Two diagnostic cohorts recorded 7382 and 3279 relay socket drops.
The LowTier server socket reported zero receive drops in those checks.
Those original eighteen trials remain in `overflow-stress.json`.
They are not the primary injected-loss comparison.

The repaired fixture requested 7340032 receive-buffer bytes.
Linux reported 8388608 bytes for the relay.
The existing node sockets reported 14680064 bytes.
The request changed only the test relay.
All nine repeated cohorts recorded zero kernel receive-buffer drops on both nodes and the relay.

All eighteen primary loss trials delivered every requested byte.
Transfer durations ranged from 2.90 to 156.68 seconds.
The userspace relay adds forwarding and queueing overhead.
Keep these results separate from direct healthy results.

## WSS baseline

WSS used its default single TCP carrier.
All twelve repeated trials delivered every requested TCP byte.
Transfer durations ranged from 6.77 to 30.26 seconds.

| Mode | Flows | Direction | Mbit/s, median [min, max] | CPU s/Gbit, median | Loaded echo p95 ms, median [min, max] |
| --- | ---: | --- | ---: | ---: | ---: |
| packets | 1 | GET | 63.21 [58.57, 66.71] | 6.28 | 245.09 [239.58, 266.48] |
| packets | 1 | PUT | 39.40 [38.14, 43.42] | 5.14 | 210.66 [181.59, 232.46] |
| packets | 4 | GET | 76.26 [59.52, 79.31] | 6.67 | 250.44 [247.63, 324.31] |
| packets | 4 | PUT | 48.58 [17.74, 51.00] | 5.72 | 319.41 [183.34, 882.13] |

The corrected probe received 784/817 UDP replies within 500 ms.
It recorded all 33 remaining replies as late.
The late replies did not stop subsequent measurements.
TCP carrier retransmitted-byte deltas ranged from zero to 305136 bytes per trial.
These are kernel TCP counters, not inner TCP retransmission totals.

The initial WSS matrix had two incomplete UDP collector records.
A stale reply triggered an assertion with an empty message.
The old result check did not reject that empty error.
A local regression reproduced the failure.
The repair records late replies separately and rejects any collector error.
The complete WSS matrix was repeated after that repair.
The initial twelve records remain in `initial-wss.json`.

WSS has no native proxy stream endpoint.
An `auto` flag cannot select a native path until that endpoint exists.
Explicit two-lane and four-lane configurations still distribute packets with inner TCP.
A native WSS protocol needs stream identifiers, admission, reset, flow control, and bounded scheduling.
It would retain outer TCP head-of-line blocking.
No native WSS gain was measured.

For a framing estimate, an eight-byte stream header plus WebSocket framing adds sixteen upstream bytes per 16 KiB chunk.
That is about 0.098% relative to application payload.
The corresponding downstream estimate is about 0.073%.
This excludes TLS, outer IP/TCP, setup, control frames, and retransmissions.
The current plain IPv4/TCP packet path adds 56 bytes before WebSocket framing for up to 1240 application bytes.
Neither calculation establishes measured complete-wire savings.

## Memory and incremental work

| Case | Mode | jpaws sampled RSS MiB | LA sampled RSS MiB |
| --- | --- | ---: | ---: |
| Healthy QUIC | off | 20.91–59.16 | 27.66–70.34 |
| Healthy QUIC | on | 15.89–29.54 | 27.44–37.46 |
| Healthy QUIC | auto | 16.80–34.68 | 27.57–38.20 |
| Injected-loss QUIC | off | 12.91–30.79 | 27.66–32.06 |
| Injected-loss QUIC | on | 20.14–35.09 | 27.29–33.20 |
| Injected-loss QUIC | auto | 27.32–35.43 | 27.16–32.54 |
| Healthy WSS | packets | 11.17–44.48 | 26.10–61.79 |

Let `F` be new flows and `B` be application bytes.
The new health policy adds `O(F)` work and no work proportional to `B`.
A successful automatic admission takes two health-state locks.
It reuses the endpoint's existing health record.
It adds no payload frame, background health probe, or carrier handshake.
An explicit remote refusal can add one failed CONNECT exchange before packet selection.
Cooldown suppresses repeated exchanges.

Each native stream reserves 64 KiB of copy-storage charges.
The maximum is 32 streams and 2 MiB of such charges per endpoint.
This is not a bound on total RSS or kernel socket memory.
The owned copy future now retains its permit through completion, error, or cancellation.
Upload FIN alone does not release it.

The initial capacity test exposed early permit release.
Rust captured the used stream fields but omitted the unused permit field from the returned future.
The new regression failed before the repair.
The repaired WAN case retained all 32 slots and selected packets for all additional automatic requests.
The first invalid capacity result remains in the command audit.

QUIC keeps its existing receive and send limits.
The stream receive cap is 2 MiB.
The connection receive cap is 4 MiB.
The connection send window is 2 MiB.
At 112 ms RTT, that send window corresponds to about 150 Mbit/s before overhead.
The admission policy does not raise that bound.
It does not change pacing, congestion control, or public packet format.
