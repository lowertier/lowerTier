# Direct and LowTier speed to sb.443.li, November 14, 2026

The measured LowTier gap is approximately seven percent in each direction.
Small TCP segments are a major contributor to the download gap.
These results apply to the native Mac at `10.126.126.2` and s6916.
They do not establish the cause of a larger gap on another client.

## Endpoint and method

`sb.443.li` resolves to `193.32.149.82`.
This address belongs to s6916, whose LowTier address is `10.126.126.60`.
The server retains kernel mode and its authenticated direct connections.
The running application remains version 0.03, build `d91b334a`.

Each TCP trial used one stream, two warmup seconds, and ten measurement seconds.
The Mac used iperf 3.22.

## Cause and limits

The Mac overlay interface has MTU 1280.
The server TAP interface has MTU 1260.
The original public host route has MTU 1500.
Both directions report TCP MSS 1208 through LowTier and 1368 through the original direct route.
Server TCP snapshots confirm these MSS values in the route controls and restoration checks.

At 500 Mbit/s, MSS 1208 requires approximately 51,738 full data segments each second.
MSS 1368 requires approximately 45,687.
The smaller MSS increases the segment count by approximately 13.2 percent.
At a 12 ms RTT, the same payload rate requires approximately 750,000 bytes in flight.

The direct MTU control reproduces the LowTier download range without LowTier carrying the bulk data.
Restoring the original route restores approximately 494 Mbit/s download.
This supports packet size and TCP behavior as major causes of the measured download difference.
It does not isolate the exact kernel TCP mechanism.
The upload control varies more and does not establish the same attribution.

LowTier also adds packet headers, encryption, packet processing, and local queueing.
The source retains separate inner TCP and outer transport control.
The connection selector uses fresh speed samples and latency.
It keeps each selected flow on its connection while that connection remains valid.
The measurements do not isolate the throughput cost of each component.

These results do not justify a fleet MTU increase.
Any larger inner MTU must fit the actual outer path and preserve delivery across retained transports.
The later [fleet MTU audit](fleet-mtu-20261114.md) selects a common effective MTU of 1280 after separate source and delivery checks.
That audit retains the outer QUIC fallback and throughput limits.
The earlier kernel repair removed the userspace endpoint from s6916.
It did not establish direct-path throughput parity or repair the underlying userspace TCP implementation.

Relevant source:

- `lowertier/src/instance/virtual_nic.rs`: effective interface MTU and native interface handling.
- `lowertier/src/tunnel/quic.rs`: datagram framing, fragmentation, pacing, and queue limits.
- `lowertier/src/tunnel/quic/tunnel_cc.rs`: outer congestion controller selection.
- `lowertier/src/peers/peer.rs`: connection selection and flow retention.
- `lowertier/src/peers/receiver_pacing.rs`: receiver pressure and pacing.

## Recovery and evidence

The initial MSS socket control failed with `Invalid argument` on the Mac.
Apple XNU source restricts the requested MSS against the socket's current segment limit.
This reference does not establish every detail of the running Darwin build.
The failed trial remains excluded from the throughput results.

The replacement control changed only the direct host-route MTU to 1260.
A guarded cleanup restored MTU 1500.
The subsequent direct trials confirmed MSS 1368 and the original throughput range.
Application binaries, node settings, and services were not replaced.
The retained kernel baseline remains active.

Some source reads used absent file paths.
File discovery located the current modules.
The missing `pidstat` tool was replaced with direct procfs sampling.
The failure records remain in the local audit.

Each trial retains commands, working directories, timestamps, process IDs, output, and exit status.
The telemetry records retain packet counts, I/O bytes, queue counters, sampled stages, CPU samples, and RSS samples.
