## 测量口径

累计 100 组有效网络/资源测量：C4 基线 24、R5 初版 24、R6 细化版 24、分配器参数对照 16、同期 WSS 确认 12。编译干扰样本单独保留并排除。完整矩阵为原生 TUN、公网认证直连、内层 MTU 1280、同一端点对及相同连接角色，每项两次，预热 3 秒、正式测量 15 秒。

CPU 100% 为一个逻辑核；记录目标 core 进程的用户态与内核态时间。CPU 秒/Gbit 以中央稳定采样区间的平均核数除以接收端有效 Gbit/s。RSS 峰值是 250 ms 采样观察到的最大值，包含共享映射。macOS physical footprint 单列；UTM PSS/私有页数据不可用，未视作零。

每版本、每方向一次确认，目标发送速率为 300 Mbit/s；这是固定负载确认，不与上面的双重复满速矩阵混合。

这一确认窗口内，UTM CPU/Gbit 上传下降 6.31%、下载下降 12.87%；RSS 峰值分别下降 38.81%、43.03%。osku 上传 CPU/Gbit 近似不变，下载上升约 10%；physical footprint 从约 11.95 MiB 增至 12.59 MiB。上述结果不能推广为所有场景的保证。

同期满速对照中，WSS 单流上传 C4 624.00 → R6 557.23 Mbit/s，四流上传 515.89 → 402.67 Mbit/s；回退约 10.70% 和 21.95%。因此本轮不将 R6 提升为默认运行基线。

## 确认的局部收益与保留问题

独占接收缓冲微基准处理 16,384 个 1,280 字节包时，转换阶段额外分配由 16,384 次降为 0；共享或过大底层缓冲仍按需复制。此计数不包含输入构建，微基准时间不作为 VPN 吞吐证据。

页面故障显著减少不等于全部内核态 CPU 成本消失。部分方向的 RSS、physical footprint、CPU/Gbit 仍有回退；整体 footprint/CPU 目标尚未全面达成。此次没有修改用户态 TCP 空闲收缩逻辑，原生 TUN 结果也不能代替用户态代理模式的测量。

## 运行基线与清理

运行基线继续为 C4/WSS，active-baseline 链接保持 candidate4。两端常驻二进制 hash 已核对；没有用较慢的新候选替换现有基线。所有本轮 benchmark core、测试 TUN、测试监听及自有 STUN helper 已停止，归档基线和原始证据保留。常驻网络的既有引导连通性问题未在本轮修改，隔离公网直连测试的成功不代表该问题已修复。
